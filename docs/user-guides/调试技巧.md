# 调试思路和手段

## 回顾SUDA架构图
SUDA架构中，用户通过调用SUDA API控制SUDA CSD，实际SUDA API会进一步调用libnvme和liburing的函数，将nvme命令传递至内核态。内核态的SUDA驱动实际包含两个部分：nvmq和qdma。nvmq会对nvme命令进行处理，比如对用户要求处理的虚拟地址转换为实际的物理地址，然后调用qdma将nvme命令传递至SUDA CSD。nvme command会经过qdma->mcdma，以数据流的方式保存到设备内存，并通知SUDA CSD的软件栈，软件栈会对命令进行处理，如果需要调用算子，再调用FPGA的辅助调度器->FPGA的算子控制器->FPGA算子完成计算。

```shell
    -machine accel=kvm \

    -smp 4 \

    -drive file=$OSIMGF,format=raw \

    -device virtio-9p-pci,fsdev=fs1,mount_tag=suda \
    -monitor unix:./qmp-sock,server,nowait \
    -serial stdio 

```

## 我的板卡卡死了，我想不重启主机重启板卡

首先运行`suda/host/util/test.sh`脚本，将板卡的pcie的错误信号屏蔽，避免因为板卡重启而导致服务器重启：
```shell
sudo bash test.sh 3b:00.0
```
然后进入Xilinx安装目录`Xilinx_2020.2/Vitis/2020.2/bin`，运行xsct

```shell
./xsct
connect
targets
```
`targets`列出了所有的FPGA板卡，因此需要选择需要重置的对应PSU，演示上只有一个设备，所以选择PSU 5：

```shell
tcfchan#0
xsct% targets                                                                                                                                                 
  1  PS TAP
     2  PMU
     3  PL
        4  Legacy Debug Hub
  5  PSU
     6  RPU (Reset)
        7  Cortex-R5 #0 (No Power)
        8  Cortex-R5 #1 (No Power)
     9  APU
       10  Cortex-A53 #0 (Running)
       11  Cortex-A53 #1 (Running)
       12  Cortex-A53 #2 (Running)
       13  Cortex-A53 #3 (Running)
xsct%       
```
接下来选择5号PSU，进行重置：

```shell
targets 5
rst -system
con
```

接下来板卡就会重启，但是主机会找不到对应的PCIe设备，因此需要重新枚举：

```shell
echo 1 > /sys/bus/pci/devices/0000\:3b\:00.0/remove
```
让板卡pcie上游的设备重新检查：
```shell
echo 1 > /sys/bus/pci/devices/0000\:3a\:00.0/rescan
```

## 我新生成了设备树/内核/比特流，但是我只想临时测试

首先，还是按照上述流程启动板卡，使用串口连接板卡，在板卡UBOOT启动期间输入Enter进行打断，可以参考下面的内容配置（需要理解UBOOT代码的内容）：

```shell
mw 0xFF0A0244 0x00000318
mw 0xFF0A0248 0x00000318
mw 0xFF0A0044 0x00000008

fatload mmc 0:1 0x10000000 env.txt
env import -t 0x10000000 $filesize

setenv recovery_fdt_addr_r 0x50000000
setenv recovery_kernel_addr_r 0x51000000
setenv bitstream_addr_r 0x50000000
setenv recovery_bitstream_addr_r 0x55000000

fatload mmc 0:1 $kernel_addr_r Image
fatload mmc 0:1 $fdt_addr_r zynqmp.dtb


if test "${flow}" = "old_sd_flow";
then
echo "Executing old_sd_flow";
else
fatload mmc 0:1 $bitstream_addr_r system.bit;
setenv bitstream_size $filesize;
fi; 

if test "${all_recovery}" = "true";
then
setenv recovery_bit "true"
setenv recovery_dtb "true"
setenv recovery_kernel "true"
fi;

if test "${recovery_bit}" = "true";
then
fatload mmc 0:1 $recovery_bitstream_addr_r golden_system.bit;
fatwrite mmc 0:1 $recovery_bitstream_addr_r system.bit ${filesize};
fi;

if test "${recovery_dtb}"  = "true";
then
fatload mmc 0:1 $recovery_fdt_addr_r golden_zynqmp.dtb;
fatwrite mmc 0:1 $recovery_fdt_addr_r zynqmp.dtb ${filesize};
fi;

if test "${recovery_kernel}" = "true";
then
fatload mmc 0:1 $recovery_kernel_addr_r golden_Image;
fatwrite mmc 0:1 $recovery_kernel_addr_r Image ${filesize};
fi;


if test "${flow}" = "old_sd_flow";
then
echo "Continue";
else
fpga loadb 0 $bitstream_addr_r $bitstream_size;
fi;

setenv -f ethaddr "18:0a:35:e3:00:4e"
setenv -f eth1addr "18:0a:35:e3:10:4e"

setenv bootargs root=/dev/mmcblk0p2 rw rootwait clk_ignore_unused cpuidle.off=1
booti $kernel_addr_r - $fdt_addr_r

```
