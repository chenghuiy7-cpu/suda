# TPC-H lineitem FPGA filter test

This directory keeps the real TPC-H data adapter separate from the existing
selective-filter application. The unmodified data generator is tracked as the
`third_party/tpch-dbgen` Git submodule. It produces the pipe-delimited
`lineitem.tbl`; `convert_lineitem.py` parses its 16 standard columns and emits
fixed 512-byte little-endian records accepted by the FPGA filter.

This is a functional test using dbgen data. It is not a published or audited
TPC-H benchmark result. TPC-H and its tools are subject to the TPC terms.

## Record layout

All fields used by the FPGA are in the first 64-byte AXI beat:

| Offset | FPGA type | TPC-H value |
|---:|---|---|
| 0 | `u64` | `l_orderkey` |
| 8 | `u64` | `l_partkey` |
| 16 | `u64` | `l_suppkey` |
| 24 | `u8` | `l_linenumber` |
| 25 | `u8` | integral `l_quantity` |
| 26 | `u8` | ASCII `l_returnflag` |
| 27 | `u8` | ASCII `l_linestatus` |
| 28 | `u8` | enumerated `l_shipmode` |
| 29 | `u8` | enumerated `l_shipinstruct` |
| 32 | `u64` | `l_extendedprice` in cents |
| 40 | `u16` | `l_discount` in basis points |
| 42 | `u16` | `l_tax` in basis points |
| 44 | `u32` | `l_shipdate` as `YYYYMMDD` |
| 48 | `u32` | `l_commitdate` as `YYYYMMDD` |
| 52 | `u32` | `l_receiptdate` as `YYYYMMDD` |
| 56 | `u64` | one-based source `.tbl` row number |

The record also retains the original strings and the complete original
pipe-delimited row: ship instruction at offset 64, ship mode at 96, comment at
112, raw-line length at 160, and raw line at 164. Unused bytes are zero.

## Query

The test uses the five filtering terms from TPC-H Query 6:

```sql
SELECT quantity FROM lineitem
WHERE shipdate >= 19940101
  AND shipdate < 19950101
  AND discount_bp >= 500
  AND discount_bp <= 700
  AND quantity < 24
```

TPC-H Q6 normally aggregates discounted revenue. The current FPGA graph
projects `quantity:u8` into LWE encryption, so this test exercises Q6's full
row predicate but does not perform its revenue multiplication or `SUM`.

## Usage

Initialize the submodule once:

```bash
cd /mnt/suda
git submodule update --init third_party/tpch-dbgen
```

Generate SF=1 `lineitem.tbl`, convert the first 128 rows, and run unit tests:

```bash
cd /mnt/suda/host/applications/tpch-lineitem-fpga-test
./run_tpch_filter_test.sh --prepare
```

Preparation also decodes every generated binary row and compares it with the
original `.tbl` row, including the retained raw text and the Q6 selection.
The generated `.tbl` is about 760 MB at SF=1 and remains outside the SUDA Git
tree. The 64 KB converted test image stays under this application's ignored
`testdata/` directory.

Write the converted data at LBA 65536 with readback verification:

```bash
./run_tpch_filter_test.sh --write
```

`--write` and `--run` reuse the prepared binary, so they do not regenerate the
full SF=1 table inside the QEMU guest.

Run the complete SSD-to-filter-to-LWE-to-Host test:

```bash
set -o pipefail
./run_tpch_filter_test.sh --run 2>&1 | tee tpch_lineitem_q6_run.log
test_rc=${PIPESTATUS[0]}
printf 'test_exit_code=%s\n' "$test_rc"
```

Environment variables can override the defaults:

```text
TPCH_SCALE=1
TPCH_RECORDS=128
TPCH_SKIP_ROWS=0
TPCH_DATA_DIR=/tmp/tpch-sf1
TPCH_SSD_DEVICE=/dev/nvmq0n1
TPCH_SSD_NSID=1
TPCH_SSD_LBA=65536
TPCH_LWE_KEY=/mnt/suda/device/operators/hls/lwe_encrypt/testdata/psi64_big_lwe_secret_key.bin
```

For the first 128 rows of the standard SF=1 data generated by this submodule,
the expected selected quantities are `[21, 23, 13, 19, 14]`; the expected
decrypted prefix is `15170d130e`, selected count is 5, and HPU-native physical
ciphertext payload is 491520 bytes. The expected 128-row binary SHA-256 is
`1d7c173a673471debd3ecc8e20af91de90674e77961441f11e32adb55766405f`.
